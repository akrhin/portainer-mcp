# Next Goal: все 11 наборов на живом Portainer, затем v0.1.0

Статус: **в работе**

## Не-цели

- Ресурсы и промпты MCP: сервер остаётся набором тулов.
- Свой UI, кэш ответов, ролевая модель внутри сервера.
- Поддержка Portainer CE отдельной веткой: спека одна, различия отдаёт сам сервер.

## Этапы

| Этап | Что проверяем | Статус |
| --- | --- | --- |
| 0 | Каталог как данные управляет регистрацией; `read_only`, `instance`, `outputSchema` | сдано, принято |
| 1 | Все 288 операций Portainer и 108 Docker Engine живут в каталоге как данные, `--exhaustive` включает их без правок кода | в работе |
| 2 | Наборы `core`, `docker`, `stacks`, `swarm` работают на живом инстансе | ждёт этап 1 |
| 3 | `k8s` + `helm`, тяжёлые ответы обрезаются, `managedFields` вырезаются | ждёт этап 2 |
| 4 | `edge`, `gitops`, `admin`, `observability`, `raw` | ждёт этап 3 |
| 5 | Доки по фактам кода, CHANGELOG, тег `v0.1.0`, репозиторий открыт | ждёт этап 4 |

Зачем этап 1: если тул описывается данными (метод, путь, схемы, аннотации), то покрытие
растёт правкой YAML, а не кодом — и 475 тулов официального сервера не нужны, чтобы
«покрывать всё».

Ворота каждого этапа:

```sh
make check && bash scripts/docs-check.sh
```

Плюс живая приёмка: `bash scripts/smoke.sh <config>` против настоящего Portainer.

## Проверка человеком

- `tools/list` показывает только включённые наборы, число тулов совпадает с каталогом.
- `--read-only` не оставляет ни одного write-тула.
- Ошибка Portainer (401, 404, 400) приходит как `isError` с текстом сервера.

## Стоп-точка

Релиз `v0.1.0` опубликован, репозиторий публичный, все 11 наборов включаются.
